# 코디세이 2주차 · 사자성어 퀴즈

사자성어의 뜻을 읽고 네 개의 보기 중 알맞은 말을 고르는 Python 터미널 게임입니다. 기본 문제 5개로 시작하며, 사용자가 직접 문제를 추가할 수 있습니다. 한 판을 끝내면 맞힌 문제 수를 기록하고, 다음 실행에서 이전 점수를 다시 볼 수 있습니다.

## 주제 선정 이유

사자성어는 뜻 하나를 질문으로, 짧은 단어 네 개를 보기로 구성하기 쉽습니다. 예를 들어 “상대방의 처지에서 생각해 본다”라는 뜻을 보고 ‘역지사지’를 고르는 방식입니다. 같은 형식으로 새 문제를 만들면서 Python의 입력 검증, 객체를 이용한 채점, JSON 파일 저장을 한 프로그램에서 연습할 수 있어 이 주제를 선택했습니다.

## 실행 방법

실습 환경은 Windows, Python 3.12.6, VS Code, MSYS2 UCRT64 Bash입니다. Python 표준 라이브러리만 사용합니다. 처음 내려받아 실행할 때는 다음 명령을 입력합니다.

```bash
git clone https://github.com/skypark-kr/week2.git
cd week2
python main.py
```

이미 저장소를 내려받았다면 `main.py`가 있는 폴더에서 `python main.py`를 실행합니다. 메뉴 번호를 입력하고 Enter를 누르면 해당 기능이 시작됩니다.

## 메뉴와 기능

| 번호 | 메뉴 | 동작 |
| --- | --- | --- |
| 1 | 퀴즈 시작 | 등록된 문제를 순서대로 풉니다. 매 문제의 정답 여부를 바로 알려 주고, 오답이면 정답 번호를 표시합니다. 끝까지 풀면 한 판의 점수를 저장합니다. |
| 2 | 퀴즈 추가 | 질문, 보기 4개, 정답 번호(1~4)를 입력하면 새 문제를 목록 끝에 추가하고 저장합니다. |
| 3 | 퀴즈 목록 | 등록된 문제 수와 각 질문을 번호순으로 보여 줍니다. |
| 4 | 점수 확인 | 완료한 게임의 점수를 회차순으로 보여 줍니다. 기록이 없으면 '점수가 없습니다.'를 표시합니다. |
| 5 | 종료 | 게임을 마치고 터미널로 돌아갑니다. |

메뉴나 정답 번호에 빈 값, 문자 또는 범위를 벗어난 숫자를 입력하면 같은 항목을 다시 묻습니다. 문제를 추가할 때도 빈 질문이나 빈 보기는 다시 입력받습니다.

## 파일 구조와 실행 흐름

| 변경할 기능 | 파일 | 관련 함수·메서드 |
|---|---|---|
| 메뉴 표시·입력·종료 | `main.py` | `show_menu()`, `read_number()`, `QuizGame.run()`, `main()` |
| 한 판 진행·문제 추가·목록·점수 조회 | `main.py` | `play_quiz()`, `add_quiz()`, `list_quizzes()`, `show_scores()` |
| 한 문제의 보기 출력·정답 판정 | `quiz.py` | `Quiz.show()`, `Quiz.is_correct()` |
| 기본 문제 편집 | `quiz_data.py` | `create_default_quizzes()` |
| 게임과 저장 데이터 사이의 변환 | `storage.py` | `quiz_rows()`, `load_quizzes()`, `save_quizzes()`, `load_scores()`, `save_scores()` |
| 파일 검증·백업·복구 | `storage.py` | `read_state()`, `write_json()`, `save_state()`, `load_state()` |

메뉴 1을 누르면 `QuizGame.play_quiz()`가 목록에서 문제 하나를 꺼내 `quiz.show()`로 보기를 표시합니다. 이어 `read_number()`가 받은 번호를 `quiz.is_correct(selected)`에 전달하고, 마지막 문제까지 풀면 `save_scores()`로 한 판의 결과를 기록합니다.

**클래스를 선택한 이유.** 함수만으로 구현하면 문제를 출력하거나 채점할 때마다 질문·보기·정답을 인자로 전달할 수 있습니다. 이 게임에서는 세 값이 항상 한 문제에 속하므로 `Quiz` 객체에 묶었습니다. `QuizGame`은 메뉴를 오가며 사용하는 문제 목록을 보관합니다. 한 판의 정답 수는 `play_quiz()` 안의 지역 변수로 두어 다음 판을 시작하면 0부터 셉니다.

**입력과 저장을 분리한 이유.** `main.py`는 사용자가 잘못 입력했을 때 어떤 안내를 보여 주고 다시 물을지 결정합니다. `storage.py`는 파일에서 읽은 데이터도 검증합니다. 이렇게 분리하면 입력 문구를 바꿀 때 저장 형식을 건드릴 필요가 없고, 파일을 직접 편집해 잘못된 정답 번호가 들어가도 불러올 때 발견할 수 있습니다.

## 저장 형식

`storage.py`와 같은 폴더의 `state.json`에 문제와 점수를 UTF-8 JSON으로 저장합니다. 다음은 문제 한 개와 점수 한 건으로 줄인 예시입니다.

```json
{
  "quizzes": [
    {
      "question": "지난 잘못을 고쳐 바른길로 돌아간다",
      "choices": ["이심전심", "개과천선", "유비무환", "동문서답"],
      "answers": 2
    }
  ],
  "scores": [{"correct": 1, "total": 1}]
}
```

| 필드 | 타입 | 필수 여부와 의미 |
|---|---|---|
| `quizzes` | 배열 | 필수. 출제 순서대로 문제 객체를 담습니다. |
| `quizzes[].question` | 문자열 | 필수. 공백만 있는 질문은 거부합니다. |
| `quizzes[].choices` | 문자열 배열 | 필수. 추가 메뉴에서는 보기 4개를 입력받습니다. |
| `quizzes[].answers` | 정수 | 필수. 1부터 보기 개수까지의 번호입니다. 예시에서는 2번 ‘개과천선’입니다. |
| `scores` | 배열 | 새 파일에는 빈 배열로 생성합니다. 이전 파일에서 누락되었거나 `null`이면 빈 배열로 읽습니다. |
| `scores[].correct` | 정수 | 회차마다 필수. 0 이상이고 해당 회차의 전체 문제 수 이하입니다. |
| `scores[].total` | 정수 | 회차마다 필수. 게임을 마친 시점의 문제 수입니다. |

배열은 출제 순서와 플레이 순서를 보존합니다. 배열 안에서 한 문제나 한 회차를 객체 하나로 묶으면 새 문제를 추가해도 이전 회차의 전체 문제 수가 유지됩니다.

### 저장과 복구

1. 문제 추가와 점수 기록은 모두 `save_state()`를 호출합니다. 기존 정상 상태는 `state.json.bak`에, 갱신한 상태는 `state.json`에 씁니다.
2. `write_json()`은 대상과 같은 폴더의 임시 파일에 JSON을 기록합니다. 파일을 닫은 후 `replace()`로 교체하고, 쓰기 도중 실패하면 임시 파일을 정리합니다. 권한·디스크 등의 `OSError`는 `main.py`의 종료 처리에서 오류 메시지와 함께 표시합니다.
3. 시작할 때는 원본을 먼저 검증합니다. 원본이 없거나 손상되면 백업을 읽어 원본을 복구합니다. 양쪽 모두 사용할 수 없으면 기본 문제 5개와 빈 점수 기록으로 시작합니다.

백업은 **직전 저장 한 번분**입니다. 예를 들어 5문제에서 6번째 문제를 추가한 직후 원본이 손상되면 백업에 있던 5문제와 당시 점수로 돌아갑니다.

### JSON을 선택한 이유와 한계

문제 수가 적은 터미널 게임에서는 사람이 파일을 직접 읽을 수 있고 별도 DB 설치 없이 실행할 수 있습니다. 다만 점수 한 건을 추가해도 파일 전체를 메모리에 읽고 다시 쓰며, 백업에도 전체 상태를 기록합니다. 회차가 많아져 파일이 커지거나 여러 사용자가 동시에 기록해야 한다면 SQLite에서 문제와 회차를 테이블로 나누고 트랜잭션으로 한 건씩 저장하는 편이 적합합니다.

## 실행 검증

다음은 기본 데이터로 시작해 메뉴 3을 선택한 실제 콘솔 출력입니다.

```text
퀴즈 목록 (5문제):
1. 지난 잘못을 고쳐 바른길로 돌아간다
2. 미리 준비해 두면 걱정할 일이 없다
3. 묻는 말과 전혀 상관없는 대답을 한다
4. 상대방의 처지에서 생각해 본다
5. 한 가지 일을 해서 두 가지 이익을 얻는다
```

아래 명령은 Bash에서 실행합니다. 기본 5문제 기준으로 재현하려면 저장 데이터가 없는 새 복제 폴더에서 순서대로 실행합니다.

| 테스트 | 명령 | 확인할 결과 |
|---|---|---|
| 기본 목록과 종료 | `printf '3\n5\n' \| python main.py` | 위 질문 5개가 표시되고 종료됩니다. |
| 입력 검증과 한 판 채점 | `printf '\nabc\n9\n1\n2\n1\n4\n3\n2\n5\n' \| python main.py` | 빈 값, 문자, 범위 초과에 각각 재입력을 요청합니다. 이후 한 판 결과는 5/5입니다. |
| 재실행 후 점수 조회 | `printf '4\n5\n' \| python main.py` | 첫 회차라면 `1회차: 5/5 문제 맞춤`이 표시됩니다. |
| 입력 종료 | `python main.py < /dev/null` | 메뉴 입력에서 EOF를 만나 종료 문구를 출력합니다. |

**문제 추가·복구 확인.** 별도 검증 폴더에서 5/5를 기록한 뒤 ‘금상첨화’ 문제를 추가했습니다. 다시 읽은 원본에는 문제 6개와 기존 5/5 기록이 있었습니다. 해당 검증 폴더의 원본을 손상시킨 뒤 다시 읽자 `백업에서 퀴즈와 점수를 복구합니다.`가 출력됐고 문제 5개와 5/5 기록이 복원됐습니다. 입력 중 Ctrl+C 또는 EOF로 종료하면 작성 중인 문제나 미완료 회차는 기록되지 않습니다.

커밋은 독립적으로 실행해 확인할 수 있는 기능이나 수정 하나를 단위로 합니다. 메시지 형식은 `접두어: 한 줄 요약`을 권장합니다. 새 기능은 `Feat`, 오류 수정은 `Fix`, 동작을 유지하는 구조 변경은 `Refactor`, 문서 수정은 `Docs`, 초기 설정은 `Chore`로 구분합니다.
